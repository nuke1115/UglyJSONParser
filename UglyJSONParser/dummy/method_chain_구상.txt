아이디어:

result반환 구조를 적용한 상태에서, 각 노드의 데이터에 접근하는 방법은 다음과 같다.

```
//필요한 변수들 선언
    UglyJSONParser::JSONParser parser;
    UglyJSONParser::RootNode root;
    std::string json = "{\"key\":\"value and this is \\\"value\\\"\",   \"arr\" : [1,1e+4,1.234]}";

    //string을 기반으로 JSONTree 생성
    parser.BuildJSONTreeFromString(json, root);
    auto value1 = root["arr"].GetValueRef()[0].GetValueRef().AsInt().GetValue();//값 검사 안하고 했을 때

    
    auto res1 = root["arr"];
    if (!res1.HasValue())
    {
        return;
    }
    auto res2 = res1.GetValueRef()[0];
    if (!res2.HasValue())
    {
        return;
    }
    auto res3 = res2.GetValueRef().AsInt();
    if (!res3.HasValue())
    {
        return;
    }
    auto value2 = res3.GetValue();//값 검사 하면서 했을 때
    //둘 다 일단 코드가 복잡해지고, 첫번째는 이 구조로 고친 이유가 없어짐
    //=>체인을 만들어서 하면 더 깔끔하게 할 수 있을듯?

    printf("%lld %lld\n", value1, value2);
```

저 방식의 문제점:
일단 기본저긍로, 코드가 전체적으로 길어진다라는 문제가 있다.
그리고, 첫번째는 두번쨰보다는 코드가 깔끔하나, 보안 검사를 생략해서 이렇게 구조를 뜯어고친 의미가 없다.
두번쨰는 보안검사를 하지만, 코드가 지나치게 길어진다.

위 방식들의 공통점:
함수 호출로 리턴값을 받아오고, 그걸 어딘가에 저장한 다음, 거기서 값을 꺼내와서 또 함수를 호출한다
이 방식이 반복된다.

아이디어:
일단, 저 리턴값은 값 또는 오류코드를 가지고 있다.
그리고, 거기서 값이 있는지 검사하고, 그것에서 값을 뽑아와서 리턴값 뽑아오는게 반복된다.
일단, 저런식으로 함수를 연쇄적으로 호출하는것과 관련된 패턴 중 메서드 체이닝이란 기법이 있다.
그것하고 엮어서, 리턴값을 가질 수 있는 변수를 가지는 클래스를 하나 만들자.
그리고, 거기에 그 리턴값에서 값을 뽑아 다음 상태로 진행시킬 수 있는 함수를 하나 만들고, 리턴값으로 자기 자신을 리턴하게 하자.
그 과정에서, 리턴값이 오류가 뜬다면, 몇번을 다음 상태로 진행시키든, 바로 리턴하게 만들어, 오류 상태를 보존시키게 하자.
그러면, 더 안전하고 깔끔하게 접근 가능하지 않을까?
일단, 체인에서 값을 뽑아올때는 무조건 노드의 참조로만(그 이외의 것으로 접근은 안되게. 그 이상으로 접근하려하면 오류를 발생시키게)

근데 저 방식의 문제:
몇번째 체이닝에서 오류가 터졌는지 모름

해결 아이디어:
지금 저 클래스는 내부에 현제의 상태를 저장해둔다
그리고, 오류가 터지면, 그때 그 상태 그대로 고정된다.
그렇다면, 초기화 함수를 만들고, 초기화하면 처음에 생성할 때 받았던 루트노드의 상태로 돌려놓는다.
그리고, 체이닝마다 몇번 체이닝을 했는지 카운트를 올린다.(이건 초기화하면 0으로 돌아감)
그리고, 나중에 에러 발생 위치 가져오는 함수를 하나 만들어서, 그걸 리턴하게 하면 어떨까(오류 가져오는것도 따로)
